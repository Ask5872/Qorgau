# Проверка Qorgau 1.1

Это сохранённый отчёт предыдущей версии. Текущие изменения и ручная матрица версии 1.2 — в `VALIDATION-1.2.md`. Результаты ниже не означают повторную проверку новой сборки.

Обновлено 4 октября 2026. Стенд сборки: Linux x86-64, Python 3.12.14, CPU. Проверялись код приложения, HTTP API, искусственный источник камеры и настоящие локальные модели. Физическая веб-камера, Windows hook и скорость на ноутбуке пользователя не были доступны этому стенду.

## Автоматические проверки

Набор проверки версии 1.1 включает **29 тестов**: 12 основных, 11 проверок отстранения и настройки экзамена, 4 проверки потоков камеры с искусственным источником и 2 проверки настоящих моделей из ASCII- и Unicode-папок. По умолчанию проверки настоящих моделей пропускаются без `QORGAU_TEST_VISION=1`; статус обычного прогона нужно читать с учётом этой настройки.

**Итоговый прогон: 29 тестов прошли, 0 ошибок и 0 неудачных проверок**, включая обе настоящие модели (`QORGAU_TEST_VISION=1`).

Итоговый JUnit версии 1.1 сохраняется в `test-results-1.1.xml`; `test-results.xml` относится к прежним основным проверкам; отдельные результаты загрузки из Unicode-путей — в `unicode-path-test-results.xml`. `validation-results.json` содержит машиночитаемую сводку с датами соответствующих проверок. Данные старого прогона интерфейса или модели нельзя считать повторной проверкой нового пользовательского сценария без отдельного результата.

### Жизненный цикл и доступ

- Краткий взгляд и моргание не вызывают события; низкая освещённость даёт технический сигнал.
- Временные правила создают один эпизод после задержки, а не запись на каждый кадр.
- Контроль взгляда не включается без калибровки или при отключённой опции.
- Проверены цепочка событий, решения преподавателя и выявление изменённой записи.
- Ответы сохраняются после перезапуска, незаконченная попытка отмечается прерванной.
- Проверены правила сочетаний клавиш и аварийный выход как чистые функции; это не исполнение Windows hook.
- API проходит цикл согласие → экзамен → ответ → событие → PIN → решение → экспорт → удаление.
- Проверены Origin, Host, токен изменяющих запросов, ограничение попыток PIN, экранирование HTML и защита CSV от формул.
- Сервер контролирует истечение времени и запрещает искусственные демособытия в настоящем режиме.

### Настоящий экзамен и отстранение

- Настоящий старт требует сохранённого преподавателем экзамена.
- Чтение и изменение полного набора вопросов с ключами требуют PIN-токена; обычное состояние не раскрывает ключи.
- Сервер берёт длительность из сохранённого экзамена и не доверяет длительности участника.
- Уже истёкший по таймеру экзамен завершается до применения ожидающего кадра телефона и не получает запоздалое отстранение.
- Разовая, слишком короткая или недостаточно уверенная детекция телефона не отстраняет.
- Повторные и устаревшие кадры не засчитываются как свежие подтверждения; разрыв более секунды прерывает накопление.
- Устойчивый телефон завершает попытку со статусом `disqualified`, сохраняет ответы и причину, закрывает запись новых ответов.
- Запрет новой попытки сохраняется в SQLite и после перезапуска.
- Разрешение новой попытки требует преподавателя; прежняя попытка и события остаются.
- Демонстрационный режим не используется как доказательство автоотстранения по камере.

### Раздельные потоки камеры

Синтетический источник и намеренно медленная модель позволяют проверить именно планирование работы, а не точность распознавания:

- видео продолжает обновляться чаще анализа; анализ пропускает старые кадры и использует новые;
- номера кадров не повторяются, JPEG события соответствует проанализированному кадру;
- камера безопасно останавливается из callback, освобождает ресурсы и может запускаться снова; повторный запуск не сбрасывает остановку, пока прежняя нативная модель ещё освобождает ресурсы;
- ошибка/потеря источника отражается в состоянии и не оставляет старые данные готовыми для экзамена.

## Измерение скорости с настоящими моделями

На Linux использован **искусственный поток 1280 × 720**, ограниченный приблизительно 30 кадрами/с, и настоящие ONNX Runtime / MediaPipe из архива. Получены следующие значения:

| Измерение | Результат на стенде |
| --- | --- |
| Захват искусственного источника | 29,9 FPS |
| Подготовка изображения для показа | 23,8 FPS |
| Анализ настоящими моделями | 9,5 FPS |
| Время обработки кадра анализа | 66,3 мс |
| Телефоны на пустых контрольных кадрах | Не обнаружены |

Это измерение подтверждает раздельную работу потоков и выполнение моделей на данном CPU. Оно **не измеряет физическую веб-камеру, доставку через Windows WebView на ноутбуке пользователя или точность распознавания на экзаменах**. Нулевые срабатывания на пустых кадрах не являются оценкой частоты ложных отстранений на людях.

Запрошенный режим устройства — 1280 × 720 при 30 кадрах/с; реальный драйвер может вернуть другой. Целевой показ — до 24 FPS, анализ — до примерно 10 FPS. Для оценки пользовательского ноутбука нужны показанные в приложении фактические числа и ручная проверка ниже.

## Локальные модели и ограничения детектора

Контрольные изображения проверены на предыдущей сборке 2 октября 2026, CPU, готовые модели из `models/`. Эти примеры остаются известными свойствами включённого детектора и не заменяют повторной целевой оценки:

| Контроль | Результат |
| --- | --- |
| Пустой серый кадр | 0 лиц, 0 телефонов |
| Контрольный портрет MediaPipe | 1 лицо |
| Два портрета рядом | 2 лица |
| Фото крупного телефона Smartphone Use | 1 телефон, confidence около 0,919 |
| 5 сложных изображений COCO128 с разметкой телефона | Телефон не найден при пороге 0,40 |

Порог автоотстранения 0,65 строже порога записи события 0,40. Он уменьшает число слабых подтверждений, но не гарантирует отсутствие ошибок и может увеличить пропуски. Confidence — внутренний выход модели, не измеренная вероятность правильного решения и не вероятность списывания.

Эти примеры не образуют репрезентативную выборку. По ним нельзя заявлять точность, полноту или частоту ложных отстранений на экзаменах. Телефоны вне кадра, маленькие и перекрытые телефоны остаются ограничением. Направление взгляда и работа в очках требуют отдельной проверки на людях.

Ранее также проверялся файловый источник с настоящим портретом: 30 кадров калибровки, нейтральный взгляд, генерация JPEG и освобождение ресурсов. Это не испытание физической камеры.

## Ручная проверка на вашем Windows-ноутбуке

Выполнять с тестовым участником до проведения экзаменов со значимыми результатами.

| Сценарий | Ожидаемое поведение |
| --- | --- |
| Обновление существующей папки с сохранением `.venv` и `data` | Сохраняются PIN и прежние отчёты |
| Первый настоящий запуск без сохранённого экзамена | Старт закрыт, предложена настройка преподавателем |
| Свои вопросы, время, импорт JSON и сохранение | Новая попытка использует сохранённый набор и время; ключи не видны участнику |
| Изменение вопросов во время попытки | Сервер отказывает; действующая попытка не меняется |
| Камера занята другим приложением | Понятная ошибка, экзамен не начинается |
| Хороший свет, одно лицо, ноутбук подключён к питанию | Видео идёт; записать фактические разрешение, FPS видео и FPS анализа |
| Калибровка при движении или нескольких лицах | Нестабильная позиция не принимается |
| Телефон крупно экраном и обратной стороной 2–3 с | При достаточно уверенном устойчивом обнаружении попытка прекращается; проверить разные чехлы |
| Телефон на краткий момент | Нет немедленного отстранения по одному кадру |
| Похожие на телефон предметы | Записать ложные события/остановки и обстоятельства; разобрать преподавателем |
| Маленький, перекрытый или плохо освещённый телефон | Измерить пропуски; не считать отсутствие остановки доказательством отсутствия предмета |
| Остановленная попытка → обновление страницы / перезапуск | Ответы сохранены, новый старт по-прежнему запрещён |
| Ошибочное событие → решение преподавателя → разрешение новой попытки | Предыдущий отчёт остаётся; новая попытка доступна после явного разрешения |
| Попытка новой записи ответа после отстранения | Сервер отказывает |
| Взгляд вниз/в сторону и обычное чтение текста | Проверить полезность порога и число лишних событий |
| Очки, блики, разное положение камеры | Настроить условия или отключить взгляд при необходимости |
| Второе лицо / выход участника | События после соответствующих задержек |
| Alt+Tab, Win, PrtScn, Ctrl+C/V в оболочке | Проверить блокировку и журнал именно на Windows |
| `05_start_browser.cmd` | Настоящие модели и экзамен работают; системной блокировки клавиш нет |
| `Ctrl+Shift+Q` | Попытка прервана, камера и клавиши освобождены |
| Потеря связи с интерфейсом | Примерно через 20–21 с снимается временная защита |
| Новый экзамен после завершения или разрешения преподавателем | Камера открывается снова, требуется свежая калибровка |
| Работа без интернета после установки | Основные сценарии работают локально |
| Снимки выключены / включены | Соответственно нет / есть файл эпизода и доступ преподавателя |
| Удаление попытки | Удаляются её ответы, события, решения и снимки |

Полная защищённость ОС, проверка личности, целевые precision/recall, частота ложных отстранений и достижимая скорость на пользовательском ноутбуке не подтверждены этими автоматическими испытаниями.


## Проверка нового интерфейса и видеопотока 1.1

Через jsdom и настоящий локальный HTTP API пройден полный сценарий: вход преподавателя по PIN, редактирование названия и времени, сохранение вопросов, включение камеры, калибровка, запуск реального режима, сохранение ответа, автоматическая остановка после последовательности кадров телефона и разрешение новой попытки по PIN. Получены пять частей MJPEG-потока (47 243 байта); адрес изображения не переустанавливался при опросах состояния. Ошибок JavaScript не было. Машиночитаемый результат — `ui-flow-1.1.json`.

Источник камеры в этом испытании задан программно: оно проверяет связку интерфейса и сервера, но не точность распознавания. Полный Chromium-тест в текущей среде не запущен: среда запрещает необходимые браузеру локальные сокеты, а повышение разрешений отклонено политикой исполнения. Проверка DOM не является визуальной проверкой Chromium или Windows WebView.
