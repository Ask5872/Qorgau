# Qorgau 1.6 — отдельные формы входа

Вход участника и вход преподавателя вынесены на отдельные полноэкранные страницы. Белый, чёрный и серый цвета интерфейса сохранены. Выбор роли сам по себе не открывает кабинет преподавателя: сервер по-прежнему проверяет PIN и выданный токен.

## Участник

1. Откройте форму входа участника.
2. Заполните имя и группу. Имя допускает до 100 символов, группа — до 60; пробелы в начале и конце убираются. Пустые поля не принимаются, кириллица поддерживается.
3. Войдите, включите камеру и выполните калибровку.
4. Начните экзамен и подтвердите условия локальной обработки. Повторно заполнять имя и группу не нужно.
5. После завершения просмотрите свой результат и завершите работу. Для следующего человека откроется новая форма входа.

Имя и группа связываются с попыткой на сервере. Замена этих полей только в запросе начала теста не меняет сохранённые данные участника. Профиль остаётся доступен при обновлении интерфейса в пределах текущего запуска приложения, пока участник не завершит работу или преподаватель не передаст компьютер следующему человеку.

Это локальная идентификация для отчёта, **не персональная учётная запись с паролем и не проверка личности**. Профиль входа хранится в памяти приложения; имя и группа завершённой попытки остаются в её сохранённом отчёте. Сетевые аккаунты и удалённые классы не добавлены.

## Преподаватель

1. Откройте отдельную форму входа преподавателя.
2. Введите PIN из окна запуска установленного приложения.
3. Подготовьте и сохраните экзамен в редакторе. При необходимости просмотрите журнал, результаты и отчёты.
4. Нажмите «Передать участнику». Токен преподавателя отзывается сервером, открытый редактор и отчёты очищаются из интерфейса, показывается форма входа участника.

Во время активной попытки нельзя сменить участника, сбросить его вход или перейти в другой кабинет. После остановки из-за телефона вход с другим именем не снимает запрет новой попытки: преподаватель должен отдельно разрешить её по PIN. Сброс формы входа скрывает предыдущий результат, но не удаляет отчёт и ответы.

**В `Qorgau-Preview.html` PIN равен `2026`.** Это только автономный просмотр оформления и процесса теста. В установленном приложении PIN генерируется при первом запуске и сохраняется в `data`; он показан в окне запуска. Команда `04_reset_pin.cmd` создаёт новый PIN при потере прежнего, сохраняя результаты.

## Упрощение рабочих экранов

Из интерфейса убраны раздел справки, кнопка «Как это работает», кнопки добавления искусственных событий и техническая телеметрия распознавания. На экранах остаются действия, нужные для входа, подготовки, тестирования и работы преподавателя с экзаменом и результатами.

Изменение касается отображения. Детекция телефона и предметов, учёт лиц, контроль взгляда, калибровка, автоматическая остановка по телефону, журнал и защита Windows сохранены. Показатели камеры и анализа доступны в локальном API для диагностики. Инструкции установки, ограничения и аварийный выход `Ctrl+Shift+Q` описаны в `README.md`.

## Проверка серверного входа

В `tests/test_entry.py` добавлены **28 прошедших автоматических проверок**:

- обязательный вход участника перед настоящим и демонстрационным тестом;
- Unicode, удаление краевых пробелов, обязательные поля и ограничения длины;
- отказ принимать дополнительные поля для смены роли;
- привязка имени и группы попытки к сохранённому профилю;
- блокирование смены участника во время теста и завершения очистки;
- сохранение отчётов и блокировки после телефона при новом входе;
- независимость PIN преподавателя и недоступность его API участнику;
- сохранение проверок CSRF и источника запроса.

Эти проверки используют локальный FastAPI с тестовым клиентом. Они подтверждают поведение входа и API; проверка физической камеры и блокировок Windows на реальном компьютере остаётся отдельным этапом.

## Итоговая проверка версии 1.6

- **149 автоматических тестов Python прошли**: вход, роли, ответы, ограничения, события, интеграция и приёмочные сценарии. Один предупреждающий вывод Starlette/httpx относится к тестовой библиотеке.
- **17 сценариев DOM прошли**: отдельные формы, обязательные поля, границы кабинетов, неверный PIN, передача участнику, очистка приватных данных и защита от запоздалых ответов. При ожидании смены кабинета кнопки входа не показываются.
- **7 групп проверок настоящего HTTP API прошли**: обязательная идентификация, отсутствие прав преподавателя у участника, привязка имени к попытке и сохранение блокировки после телефона.
- Полный сценарий DOM + HTTP: вход преподавателя → сохранение теста → передача участнику → вход по имени и группе → поток камеры → ответ → остановка по телефону → разблокировка по PIN. Поток MJPEG получил 5 частей, его адрес не пересоздавался при обновлении интерфейса; ошибок JavaScript нет.
- Проверка цветов HTML, CSS и JavaScript: все заданные цвета интерфейса ахроматические.

Машиночитаемые результаты: `entry-ui-check.json`, `entry-api-check.json`, `entry-http-check.json`. Для HTTP-сценария применялась управляемая тестовая камера. Результаты не заменяют проверку физической камеры и нативной защиты на компьютере Windows; браузерная геометрия здесь не проверялась.
