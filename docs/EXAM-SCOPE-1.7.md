# Qorgau 1.7 — защита только во время теста

Дата: 5 октября 2026 года.

В предыдущем запуске отдельный рабочий стол Windows создавался ещё до входа в кабинет. Теперь основное приложение открывается обычным окном. Изоляция начинается после подтверждения «Начать тест» и завершается вместе с попыткой.

## Поведение по этапам

| Этап | Поведение окна и клавиш |
| --- | --- |
| Выбор роли, вход участника или преподавателя | Обычное окно на исходном рабочем столе. Доступны сворачивание, Alt+Tab, Win, копирование и вставка |
| Кабинет преподавателя, редактор, журнал, результаты | Обычное окно; системные сочетания не блокируются |
| Подготовка участника, камера, калибровка | Обычное окно; камера сама по себе не включает защиту рабочего окружения |
| Диалог условий перед стартом | Обычное окно до подтверждения кнопкой «Начать тест» |
| Активная попытка | Отдельный рабочий стол Windows, полноэкранное экзаменационное окно, ограничения клавиш, переходов и новых окон |
| Сдача, истечение времени, остановка по телефону | Возврат на исходный рабочий стол. Прежнее окно приложения показывает результат; ограничения сняты |
| Аварийное или техническое прерывание | Сначала возвращается исходный рабочий стол, затем закрывается экзаменационное окно. Активная попытка прерывается, отправленные ответы сохраняются |

Остановка из-за телефона сохраняет блокировку новой попытки. Возврат в обычное окно её не снимает: преподаватель должен войти по PIN и разрешить новую попытку. Другие завершения также не удаляют историю и отчёты.

## Жизненный цикл Windows

Основное окно, локальный сервер и управление камерой остаются в основном процессе на исходном рабочем столе. Для каждой попытки создаются отдельный процесс наблюдения и экзаменационное окно. Наблюдатель отвечает за восстановление исходного рабочего стола и не завершает чужие программы.

Во время защищённого теста **Ctrl+Shift+Q** возвращает обычный рабочий стол и прерывает попытку. Вне теста приложение это сочетание не захватывает. Отсутствие сигнала экзаменационного окна более 15 секунд также приводит к восстановлению рабочего стола. Если защищённое окно не подготовилось за 45 секунд, запуск отменяется.

После штатного или аварийного завершения экзаменационного окна основное приложение остаётся открытым. Участник видит свой результат, преподаватель может войти по PIN, следующий участник — через свою форму. Перезапуск между попытками не требуется. Если аварийно завершился сам основной процесс, приложение нужно открыть заново; незавершённая попытка будет отмечена прерванной, сохранённые ответы останутся в базе.

## Запуск и совместимость

- `02_start.cmd` открывает обычное окно Qorgau с возможностью начать защищённый тест.
- `03_exam_windows.cmd` сохраняется как прежнее имя запуска того же режима.
- `python run.py --isolate` сохраняет совместимость прежней команды, но теперь изолирует только попытку, а не весь сеанс приложения.
- `python run.py --desktop` на Windows также поддерживает запуск отдельного защищённого теста из обычного окна.
- `05_start_browser.cmd` предназначен для диагностики камеры. Настоящий защищённый экзамен на Windows в обычном браузере не запускается.
- `Qorgau-Preview.html` и демонстрационный режим не включают настоящую камеру и защиту Windows. PIN `2026` относится только к отдельному HTML-предпросмотру.

Имеющиеся `data` и `.venv` нужно сохранить при обновлении. PIN, вопросы и результаты из прежней `data` не меняются. Отдельные формы входа и строго монохромный интерфейс сохраняются.

## Проверка и её границы

Автоматические проверки жизненного цикла используют имитации Windows API и окон, чтобы проверить условие включения защиты, отмену запуска, порядок восстановления и обработку завершения. Проверки сервера и интерфейса проверяют переходы и доступ к результатам. Они не подтверждают работу физической клавиатуры, сворачивания окон, WebView2 или переключения рабочих столов на конкретном ноутбуке.

Физическая камера и Windows-окружение недоступны на стенде сборки. Следующая матрица — **план ручной проверки на целевом компьютере**, а не перечень пройденных физических испытаний.

| Сценарий на Windows | Ожидаемый результат |
| --- | --- |
| Открыть `02_start.cmd`; войти в каждый кабинет, свернуть окно, нажать Alt+Tab, Win и Ctrl+C/V | Обычный рабочий стол доступен, системные сочетания работают |
| Включить камеру и пройти калибровку до теста | Изображение и калибровка работают; окно по-прежнему можно свернуть |
| Открыть и отменить диалог начала теста | Защищённый рабочий стол не появляется |
| Подтвердить «Начать тест» | Появляется отдельное полноэкранное окно теста; обычные программы остаются на исходном рабочем столе |
| Во время теста нажать Alt+Tab, Win, Ctrl+C/V и PrtScn | Предусмотренные ограничения активны; Ctrl+Alt+Delete остаётся системным выходом Windows |
| Завершить тест, затем отдельно проверить истечение времени | Возвращается обычный рабочий стол; результат доступен в прежнем окне; ограничения сняты |
| Подтвердить устойчивое обнаружение телефона | Попытка остановлена, ответы сохранены, рабочий стол возвращён; новая попытка требует разрешения преподавателя |
| Во время теста нажать Ctrl+Shift+Q | Возврат на исходный рабочий стол до закрытия экзаменационного окна; попытка прервана; основное окно доступно |
| Проверить сбой запуска и потерю сигнала экзаменационного окна | Рабочий стол доступен после отмены или восстановления; интерфейс сообщает о сбое |
| После завершения войти следующим участником и начать новый тест | Новая попытка запускается без перезапуска основного приложения |

Отдельный рабочий стол ограничивает доступ к обычным окнам, но не заменяет политику управляемого Windows-компьютера. Действия администратора, Ctrl+Alt+Delete, некоторые средства системной записи, удалённый доступ и внешняя камера не блокируются.

## Результаты проверки сборки

Для этой версии прошли **226 тестов Python**: обычный запуск, маршрутизация внутренних процессов, жизненный цикл изоляции, возврат рабочего стола, вход, права, ответы и остановка по телефону. Включены проверки повторной попытки и защиты от устаревшего наблюдателя предыдущего окна. Таймер запускается после подтверждения готовности защищённого окна: время его открытия не отнимается у участника.

Дополнительно прошли **8 групп DOM-проверок** области блокировки, **17 групп** регрессии двух входов и **6 проверок** готового автономного HTML. Основное окно не создаёт ложные события потери фокуса при переходе в экзаменационное; heartbeat защищённого окна поступает через его собственный интерфейс. Предпросмотр проверен на отсутствие внешних зависимостей и ошибок JavaScript. Цвета интерфейса остались монохромными.

Системные вызовы в этих тестах заменены имитациями. Приведённая выше ручная матрица Windows остаётся необходимой для подтверждения нативного поведения на целевом компьютере.
